# Go-live Data Freeze

本文件用于从 NAS 内网试点切换到公司内网正式运行前的数据冻结复核。它不允许扩大 Excel 导入范围，不新增第 9 类模板，不做覆盖式更新导入。

## 冻结范围

正式上线前必须冻结导入模板：

- 往来方/供应商。
- 物料。
- 部门与员工。
- 项目点。
- 期初库存。
- 合同到期提醒。
- 项目点现场人员。
- 健康证到期。

冻结后不得临时修改模板字段、必填规则、状态枚举或导入确认逻辑。确需调整时，必须走单独 PR、测试和重新试导入。

## 最后一次导入

上线负责人需要记录：

- 最后一次导入时间。
- 导入批次 ID。
- 模板类型。
- 操作人。
- 复核人。
- errorRows / warningRows。
- 是否已下载 error-report.xlsx。
- 是否已确认导入后复核完成。

## 导入后复核

最后一次导入完成后，需要逐项复核：

- 合同风险：确认到期合同进入合同风险或合同台账。
- 证照健康证：确认项目点健康证、公司健康证进入健康证视图，且状态正确。
- 项目点风险：确认项目点现场人员和项目点健康证影响项目点风险台账。
- 库存流水：确认期初库存进入库存流水，而不是误跳入库流水。

复核结果应写入数据冻结 signoff，并保存在 Git 仓库外。

## 正式上线后修正原则

- 正式上线后不再用 Excel 覆盖式更新。
- 错误数据应到业务模块修正/作废/停用。
- 不直接删数据库。
- 不手工修改数据库表绕过审计日志。
- 不通过普通业务页面手填 Storage Key。

## 试点数据转正式数据确认

试点数据转正式数据前，需要明确试点数据转正式数据的确认人，并记录：

- 负责人。
- 日期。
- 导入批次 ID。
- 异常项。
- 异常处理结论。
- 是否允许进入公司内网正式上线审批。
