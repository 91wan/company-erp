# Company ERP MVP 数据模板与清洗规则

版本日期：2026-05-13

本文件用于第一版 ERP 数据准备。当前只定义字段模板和人工清洗规则，不写导入代码。

## 总原则

- Excel 是第一优先级。第一批数据先按 Excel 模板整理。
- 微信记录第一版只人工摘录关键字段，不做自动解析。
- 纸质表第一版只人工录入关键字段并挂附件，不做 OCR。
- 每类基础资料都必须有稳定编码。不要用名称、手机号、合同名称当唯一主键。
- 字段先少后多。只保留 MVP 日常采购、库存、项目点、合同台账、人员权限必须用到的字段。
- 日期统一为 `yyyy-mm-dd`，例如 `2026-05-11`。
- 状态字段使用固定字典，避免同义值混用。

## 1. 供应商模板

| 字段 | 必填 | 类型 | 规则 |
| --- | --- | --- | --- |
| 供应商编码 | 是 | 文本 | 稳定唯一编码，例如 `SUP0001`。同名供应商也必须不同编码。 |
| 供应商名称 | 是 | 文本 | 使用完整名称，去掉前后空格，统一括号和空格写法。 |
| 主体类型 | 是 | 字典 | 只允许公司、个人。公司供应商/分包商填公司；个人承包人填个人。 |
| 统一社会信用代码 | 否 | 文本 | 有则填，用于辅助去重；缺失不阻止导入。 |
| 身份证号 | 条件必填 | 文本 | 主体类型为个人时必填；导入后加密保存，普通列表只显示脱敏号和后四位。 |
| 联系人 | 否 | 文本 | 多联系人先填主要联系人，其他写备注。 |
| 联系电话 | 否 | 文本 | 只保留数字、`+`、`-`；缺失允许为空。 |
| 供应类别 | 否 | 字典 | 建议：定制物料、办公物料、设备、服务、其他。MVP 不整理食材供应链。 |
| 常用物料 | 否 | 文本 | 仅作辅助说明，不作为物料主数据。 |
| 开户地址 | 否 | 文本 | 第一版只做备注型字段。 |
| 结算方式 | 否 | 文本 | 例如月结、现结、按合同。 |
| 状态 | 是 | 字典 | 只允许启用、停用。 |
| 备注 | 否 | 文本 | 记录待确认信息。 |

清洗重点：供应商名称重复时，不直接合并。先用信用代码、身份证后四位、联系人、手机号、地址、历史合同辅助判断。同一主体可以同时是供应商和分包商，不要重复建档。

## 2. 物料模板

| 字段 | 必填 | 类型 | 规则 |
| --- | --- | --- | --- |
| 物料编码 | 是 | 文本 | 稳定唯一编码，例如 `MAT0001`。 |
| 物料名称 | 是 | 文本 | 统一主名称，同义别名写备注。 |
| 规格型号 | 否 | 文本 | 影响采购或库存的规格必须填，例如 `500ml/个`、`夏季短袖`。 |
| 物料类别 | 是 | 字典 | 先少量分类，避免过细。 |
| 基本单位 | 是 | 字典 | 库存统一使用基本单位，例如 `个`、`箱`、`套`。 |
| 常用采购单位 | 否 | 文本 | 例如袋、箱、桶。 |
| 单位换算 | 否 | 文本 | 例如 `1箱=1000个`。无法固定换算则留空。 |
| 默认供应商编码 | 否 | 文本 | 不是必填；填写但未匹配供应商时只提示 warning，物料仍可导入且默认供应商留空。 |
| 安全库存 | 否 | 数字 | 没有要求可为空。 |
| 状态 | 是 | 字典 | 启用、停用。 |
| 备注 | 否 | 文本 | 记录别名、临时分类、待确认换算。 |

清洗重点：同名不同规格通常应拆成不同物料；库存数量必须统一到基本单位。MVP 物料范围是定制物料和办公室物料，不整理食材。

## 3. 采购需求模板

| 字段 | 必填 | 类型 | 规则 |
| --- | --- | --- | --- |
| 采购需求编号 | 否 | 文本 | 历史数据有编号则保留；新数据可由系统生成。 |
| 物料编码 | 否 | 文本 | 能匹配物料模板时填写，暂未建档时允许为空。 |
| 物料名称 | 是 | 文本 | 按实际需求记录，后续再归并到物料主数据。 |
| 规格型号 | 否 | 文本 | 影响采购或入库识别时必须填。 |
| 需求数量 | 是 | 数字 | 只能填正数。 |
| 单位 | 是 | 文本 | 尽量使用常用单位字典。 |
| 申请人 | 是 | 文本 | 可先填姓名，后续再匹配员工编码。 |
| 部门 | 否 | 文本 | 部门名称保持统一。 |
| 项目点编码 | 否 | 文本 | 项目点需求能确认时填写。 |
| 期望到货日期 | 否 | 日期 | 统一 `yyyy-mm-dd`。 |
| 用途/备注 | 否 | 文本 | 记录需求背景或不确定项。 |
| 状态 | 是 | 字典 | 草稿、待采购、采购中、部分到货、已完成、已取消。 |

清洗重点：采购需求可以先不匹配供应商。先保证需求物料、数量、单位、申请人可追溯。

| 采购平台/渠道 | 否 | 文本 | 平台采购建议填写，例如京东企业购、1688、淘宝、拼多多、线下门店。 |
| 平台订单号 | 否 | 文本 | 有则填写，便于查物流和对账。 |
| 店铺名/商家名 | 否 | 文本 | 没有正式供应商档案时先填文本。 |
| 供应商编码 | 否 | 文本 | 可选；能匹配供应商模板时填写。 |
| 供应商名称辅助 | 否 | 文本 | 供应商编码缺失时用于人工核对。 |
| 物料编码 | 否 | 文本 | 能匹配物料模板时填写。 |
| 物料名称 | 是 | 文本 | 至少保留实际采购名称。 |
| 规格型号 | 否 | 文本 | 与入库识别相关时填写。 |
| 采购数量 | 是 | 数字 | 只能填正数。 |
| 单位 | 是 | 文本 | 与采购数量配套。 |

| 备注 | 否 | 文本 | 异常、取消原因、沟通记录。 |

清洗重点：供应商编码不是必填。平台采购和线下采购可以先依靠采购人、采购平台/渠道、订单号、店铺名或商家名追溯。

## 5. 员工模板

| 字段 | 必填 | 类型 | 规则 |
| --- | --- | --- | --- |
| 员工编码 | 是 | 文本 | 稳定唯一编码，例如 `EMP0001`。重名员工必须不同编码。 |
| 姓名 | 是 | 文本 | 只填姓名，不混入岗位或项目点。 |
| 手机号 | 否 | 文本 | 缺失允许为空；重复手机号需人工确认。 |
| 部门 | 是 | 文本 | 部门名称先统一，例如不要混用采购、采购组、采购部门。 |
| 岗位 | 否 | 文本 | 仅作显示和管理参考。 |
| 角色 | 是 | 字典 | 系统管理员、人事、采购、仓库、项目点、市场、运营、只读；多角色可用中文顿号、中文逗号或英文逗号分隔，例如 `运营、仓库`。 |
| 负责项目点编码 | 否 | 文本 | 项目点人员必填；多项目点用英文逗号分隔。 |
| 入职日期 | 否 | 日期 | 统一 `yyyy-mm-dd`；不确定可留空。 |
| 状态 | 是 | 字典 | 在职、离职、停用。 |
| 备注 | 否 | 文本 | 记录兼职角色、临时授权等。 |

清洗重点：手机号不是唯一主键；权限以角色字段为准，项目点可见范围以项目点编码为准。

## 6. 项目点模板

| 字段 | 必填 | 类型 | 规则 |
| --- | --- | --- | --- |
| 项目点编码 | 是 | 文本 | 稳定唯一编码，例如 `SITE0001`。 |
| 项目点名称 | 是 | 文本 | 使用运营常用名称。 |
| 甲方客户/服务单位 | 是 | 文本 | 项目点对应的客户或服务单位。 |
| 服务模式 | 是 | 字典 | 只允许直营、外包。 |
| 外包方名称 | 条件必填 | 文本 | 服务模式为外包时必填；直营时必须留空。 |
| 外包方主体类型 | 条件必填 | 字典 | 服务模式为外包时填写公司或个人；个人承包人也作为分包商 Party 建档。 |
| 区域 | 否 | 文本 | 例如无锡、南京、苏州、某区。 |
| 地址 | 否 | 文本 | 能定位即可，详细门牌缺失不阻止导入。 |
| 甲方联系人 | 否 | 文本 | 客户侧联系人。 |
| 甲方联系电话 | 否 | 文本 | 缺失允许为空。 |
| 外包方联系人 | 否 | 文本 | 外包项目点可填；MVP 不给外包人员开系统账号。 |
| 外包方联系电话 | 否 | 文本 | 缺失允许为空。 |
| 负责人员工编码 | 是 | 文本 | 必须能在员工模板中找到。 |
| 服务类型 | 否 | 字典 | 食堂、团餐、后勤服务、其他。 |
| 业务项目编码 | 否 | 文本 | 自营建设或资产投入项目投运后形成项目点时填写；普通甲方食堂项目点可留空。 |
| 状态 | 是 | 字典 | 启用、停用。 |
| 备注 | 否 | 文本 | 记录别名、历史名称、待确认地址。 |

清洗重点：同名不同地址要分开建项目点；负责人员必须用员工编码关联；一个外包项目点只能有一个外包方，且外包方负责整个项目点运营。分包商本人亲自联系项目，也仍然区分两个概念：Party 是合同/项目相对方，项目点外部账号是登录入口。

## 6.1 项目点外部账号模板

此模板仅用于外包项目点的项目点外部登录账号。账号不进入员工模板，不作为合同相对方主数据，也不自动生成现场人员名单。

| 字段 | 必填 | 类型 | 规则 |
| --- | --- | --- | --- |
| 项目点编码 | 是 | 文本 | 必须能匹配项目点模板。一个项目点同一时间只能有一个启用项目点外部账号。 |
| 外包方名称 | 否 | 文本 | 用于说明账号来源；能匹配分包商 Party 时填写。 |
| 当前联系人 | 是 | 文本 | 登录账号当前保管人和通知接收人。 |
| 当前联系人手机号 | 是 | 文本 | 换人时必须更新，并同步重置密码。 |
| 登录账号 | 是 | 文本 | 系统登录名，默认使用项目点编码，必须唯一。 |
| 初始密码 | 是 | 文本 | 导入/创建后必须哈希保存，不保留明文。 |
| 状态 | 是 | 字典 | 启用、停用、锁定。 |
| 开始日期 | 否 | 日期 | 统一 `yyyy-mm-dd`。 |
| 结束日期 | 否 | 日期 | 换人或停用时填写。 |
| 备注 | 否 | 文本 | 记录换人、授权来源等。 |

清洗重点：换人时不要覆盖旧账号姓名和手机号，应停用旧账号并新增新账号；历史领用申请保留提交账号、姓名快照和手机号快照。

## 6.2 业务项目模板

业务项目用于归集自营建设/资产投入项目，例如“扬中中央厨房”。普通甲方食堂项目点不强制建立业务项目。

| 字段 | 必填 | 类型 | 规则 |
| --- | --- | --- | --- |
| 业务项目编码 | 是 | 文本 | 稳定唯一编码，例如 `BP2026001`。 |
| 业务项目名称 | 是 | 文本 | 例如 `扬中中央厨房`。 |
| 项目类型 | 是 | 字典 | 第一版固定为自营建设/资产投入。 |
| 状态 | 是 | 字典 | 筹备中、建设中、已投运、暂停、已结束、已取消。 |
| 地点 | 否 | 文本 | 项目地址或所在城市。 |
| 负责人员工编码 | 否 | 文本 | 能匹配员工模板时填写。 |
| 开始日期 | 否 | 日期 | 统一 `yyyy-mm-dd`。 |
| 结束日期 | 否 | 日期 | 项目完工、投运或结束日期；不确定可留空。 |
| 备注 | 否 | 文本 | 记录土地、土建、装修、设备等建设范围说明。 |

清洗重点：业务项目是建设/资产投入归集维度，不是普通项目点。业务项目可先独立存在；投运后如果形成一个或多个项目点，再由项目点填写业务项目编码关联。

## 7. 期初库存模板

| 字段 | 必填 | 类型 | 规则 |
| --- | --- | --- | --- |
| 仓库编码 | 是 | 文本 | MVP 固定使用无锡总部仓库，建议编码 `WH-WX-HQ`。 |
| 物料编码 | 是 | 文本 | 必须能在物料模板中找到。 |
| 物料名称辅助 | 否 | 文本 | 只为人工核对，不作为导入主键。 |
| 批次号 | 否 | 文本 | 没有批次管理可为空。 |
| 期初数量 | 是 | 数字 | 只能填非负数字，以盘点结果为准。 |
| 单位 | 是 | 字典 | 必须等于物料基本单位。 |
| 单价 | 否 | 数字 | 无财务核算要求可为空；有则先统一含税/不含税口径。 |
| 库存日期 | 是 | 日期 | 作为期初余额切换日。 |
| 存放位置 | 否 | 文本 | 例如主仓A区。 |
| 备注 | 否 | 文本 | 记录盘点差异或待确认事项。 |

清洗重点：先整理物料，再整理期初库存。单位不一致时，必须先换算到物料基本单位。

## 7.1 总部物料出库/领用模板

| 字段 | 必填 | 类型 | 规则 |
| --- | --- | --- | --- |
| 出库单号 | 是 | 文本 | 稳定唯一编号，例如 `OUT202605110001`。 |
| 仓库编码 | 是 | 文本 | MVP 固定为 `WH-WX-HQ`。 |
| 出库日期 | 是 | 日期 | 统一 `yyyy-mm-dd`。 |
| 物料编码 | 是 | 文本 | 必须能在物料模板中找到。 |
| 数量 | 是 | 数字 | 必须大于 0。 |
| 单位 | 是 | 字典 | 必须等于物料基本单位。 |
| 出库去向类型 | 是 | 字典 | 项目点、外包方、公司部门、公司个人。 |
| 项目点编码 | 条件必填 | 文本 | 出库去向类型为项目点时必填；外包方相关领用能确认项目点时建议填写。 |
| 外包方名称 | 条件必填 | 文本 | 出库去向类型为外包方时必填。 |
| 部门 | 条件必填 | 文本 | 出库去向类型为公司部门时必填。 |
| 申请人员工编码 | 否 | 文本 | 公司个人领用时如能匹配员工编码则填写。 |
| 领用人姓名 | 条件必填 | 文本 | 出库去向类型为公司个人时必填。 |
| 发放人员工编码 | 是 | 文本 | 必须能在员工模板中找到。 |
| 签收人 | 否 | 文本 | 可以是公司员工，也可以是外包方实际签收人。 |
| 用途 | 否 | 文本 | 例如工服发放、定制纸杯领用、办公室内部使用。 |
| 备注 | 否 | 文本 | 记录临时统一领料、后续分配项目点等说明。 |

清洗重点：总部物料出库只记录无锡总部仓库的定制物料和办公室物料，不记录食材，不记录项目点现场库存余额。出库去向必须能落到项目点、外包方、公司部门或公司个人之一，不能再笼统填写公司内部。

| 结束日期 | 否 | 日期 | 到期提醒以后可基于此字段做。 |
| 合同金额 | 否 | 数字 | 只填数字，默认人民币。 |

清洗重点：MVP 只做合同台账、附件挂接、项目点/业务项目归集和合同金额汇总，不做完整合同审批流程。合同方向回答“和谁签、业务关系是什么”；合同形态回答“一次性、固定期限、框架还是工程建设”；合同标的分类回答“买/做/服务的是什么”；投入分类只用于项目点或业务项目投入汇总。项目点合同必须区分甲方服务合同、外包合同和投入合同。同一项目点可以有多份甲方服务合同，也可以有多份相同投入分类合同；同一业务项目也可以有多份相同投入分类合同。不要因为项目点编码、业务项目编码、相对方名称、合同方向、合同形态、合同标的分类或投入分类相同就合并合同；必须以合同编号或合同原件为准。普通项目点投入合同填写项目点编码 + 投入分类；自营建设合同填写业务项目编码 + 投入分类；如果合同同时明确属于某业务项目和某项目点，两个编码都可以填写。

## 跨模板校验规则

- 期初库存中的 `物料编码` 必须存在于物料模板。
- 合同台账中的 `相对方名称`、`项目点编码` 应尽量能匹配对应基础资料。
- 总部物料出库中的 `仓库编码` 固定为 `WH-WX-HQ`，不整理项目点现场仓。
- 总部物料出库中的 `出库去向类型` 只允许项目点、外包方、公司部门、公司个人。
- `出库去向类型=项目点` 时必须填写 `项目点编码`。
- `出库去向类型=外包方` 时必须填写 `外包方名称`。
- `出库去向类型=公司部门` 时必须填写 `部门`。
- `出库去向类型=公司个人` 时必须填写 `领用人姓名`；如能匹配员工编码则同时填写 `申请人员工编码`。
- 证照与资质台账中的 `归属对象编码` 应尽量匹配员工、项目点、供应商或公司资料；暂时不能匹配时保留归属对象名称并标记待复核。
- 证照与资质台账中只有 `有效期类型=固定到期` 时才强制要求到期日期；不得为无明确到期日的证照编造日期。
- 采购记录中的 `供应商编码` 可为空；不得因为缺少供应商而阻止采购记录整理。
- 采购记录必须有采购人和采购来源类型。
- 员工的 `负责项目点编码` 必须能匹配项目点模板。
- 微信记录可以先保留原始物料名称，但转正式业务单前应匹配到物料编码。
- 所有状态字段必须来自字典，不接受自由填写。
- 所有金额、数量、单价字段只填数字，不加中文单位或货币符号。
- 所有日期字段不填模糊日期；无法确认具体日期时留空并备注。

## 第一批整理顺序

1. 先整理供应商、物料、员工、项目点四类基础资料。
2. 再整理期初库存，因为它依赖物料编码和仓库口径。
3. 再整理采购需求和采购记录；采购记录允许先没有供应商编码。
4. 再整理合同台账，因为它依赖供应商和项目点。
5. 后期再整理证照与资质台账；有固定到期日的先录入到期日期，无明确到期日的先做附件归档和人工复核日期。
6. 微信记录和纸质表作为补充台账，先做人工摘录和附件挂接。
7. 导入前做一次编码、必填字段、日期、数字、单位、状态字典检查。
