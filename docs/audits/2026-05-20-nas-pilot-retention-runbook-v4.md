# NAS pilot retention runbook v4

Date: 2026-05-20

Scope: NAS intranet trial evidence retention and verification. This runbook does
not deploy NAS, does not read production data, and does not approve public
internet access.

## Judgment

The current build can enter a controlled NAS intranet trial after the evidence
package below is captured and reviewed. 可进入 NAS 内网试点，但不是正式合规档案系统全面上线.

## Evidence package structure

Store the trial evidence outside Git. A complete evidence directory should
contain:

- `summary.txt` from `npm run pilot:verify-local -- --evidence-dir <outside-git-path>`.
- `environment-checks.txt` from the same local verification run.
- `legacy-report-dry-run.txt` and `legacy-report.json`; if
  `PILOT_LEGACY_REPORT_DATABASE_URL` was not provided, `legacy-report.json` must
  explicitly record `SKIPPED`.
- `manifest.json` and `manifest.sha256` generated by the verification script.
- `audit CSV` export from `/api/audit-logs/export.csv`, using the same filters
  shown in the UI.
- `deploy revision` record: Git commit, build time, deployment operator, and PR
  or release reference.

## Integrity checks

Before sign-off, the operator must verify:

- `manifest.sha256` matches the current `manifest.json`.
- Every file listed in `manifest.json` exists and its recorded SHA256 matches the
  file bytes.
- The audit CSV export response headers include the record count and SHA256; the
  exported file's SHA256 is recorded beside the filter conditions.
- The legacy attachment report is count-only and does not contain raw paths,
  `Storage Key`, NAS storage roots, attachment bytes, or real business data.
- The reviewer records the 责任人, review time, filter conditions, and deploy
  revision next to each retained export.

## Role coverage

Retain a short browser QA note for each role:

- `admin`: can see Dashboard, project-site risk ledger, global attachment
  management, audit logs, audit CSV export, and System Settings.
- `viewer`: read-only; cannot mutate business records, manage attachments, or
  export audit logs.
- `project_site`: scoped to assigned project-site data; cannot see global
  inventory value, cost, purchase price, stock amount, or unrelated project
  sites.
- `external_project_site`: portal-only; can use scoped material request and
  compliance sections, but cannot see System Settings, audit logs, global
  attachment management, `Storage Key`, raw paths, other project sites, cost,
  purchase price, or stock amount.

## Attachment and audit boundaries

- 附件 scope must be checked with list, detail, download-url, content, headquarters
  upload, and external business-object upload flows.
- Business pages must use unified attachment references; legacy
  `attachmentPath`, `sourceAttachmentPath`, and `filePath` fields are migration
  references only.
- Audit export remains admin-only and must retain action, entityType,
  actorUsername, and date range filters.
- Audit content must remain redacted: no password, token, cookie, full identity
  number, server absolute path, raw secret, or real attachment path.

## Public exposure boundary

禁止公网暴露 API/PostgreSQL. The trial remains NAS intranet only.

Public or cross-network access requires a later dedicated gate covering HTTPS,
`PUBLIC_ACCESS_ENABLED=true`, `AUTH_COOKIE_SECURE=true`, HTTPS-only CORS origins,
Origin/CSRF verification, audit review, attachment upload/download review, and a
fresh restore drill.

## Formal rollout gaps

Before treating the system as a formal compliance archive, complete separate
work for historical attachment migration, OCR/preview, long-term archival
policy, restore rehearsal records, and business-side compliance acceptance.
