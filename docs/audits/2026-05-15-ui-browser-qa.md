# UI Browser QA 可用性 Audit

日期：2026-05-15

## 范围

本轮只审查 Web UI 的真实浏览器可用性，不改后端 API、Prisma schema 或权限矩阵。Browser QA 使用 Playwright mock API，不连接 NAS、不连接真实数据库、不写入业务数据。

覆盖角色：

- admin：完整总部后台导航与关键工作区。
- viewer：只读工作区，不显示新增/保存等管理动作。
- project_site：只显示项目点领用相关入口，不显示全局库存余额入口或出库动作。
- external_project_site：只进入项目点门户和必要资料提交入口，不显示完整 ERP 导航。

覆盖页面：

- Dashboard 总览
- 采购
- 库存
- 项目点
- 证照资质
- 合同
- 业务项目
- 人员权限
- Excel 导入
- 系统设置

覆盖浏览器断言：

- 页面非空白，无 Vite overlay，无 console error。
- 主要总部工作区都有可见页面标题。
- Dashboard 没有硬编码 “Admin” 问候和假通知数字。
- 抽屉表单与详情抽屉可打开、关闭，并且关闭后不会遮挡后续导航。
- external_project_site 不显示完整 ERP 导航、采购/库存/合同/人员权限入口、成本/采购价/库存金额或其他项目点内容。
- 1365x900、390x844、1920x1080、1024x768 下主内容和表格保持可用，表格横向滚动容器存在。

## 已修复项

1. 外部项目点门户文案暴露了“成本金额”和“其他项目点”字样。
   - 修复：改为“内部金额”和“非绑定资料”，避免给外部项目点账号展示成本或跨项目点操作暗示。

2. 移动端库存页里，入库登记表单可能覆盖库存流水表格点击区域，导致详情抽屉无法打开。
   - 修复：`people-section-grid` 在 1180px 以下切换为单列布局，避免表单与表格横向挤压和遮挡。

3. E2E 覆盖不足，未显式巡检所有总部工作区标题、抽屉关闭后的导航可用性、1920/1024 响应式宽度。
   - 修复：补充 Playwright 用例覆盖完整后台巡检、FormDrawer/DetailDrawer 交互、external_project_site 敏感信息不可见和宽屏/平板布局。

## 未修复但非阻断项

- 基础资料是组合工作区，当前由“往来单位”和“物料与仓库”两个子 PageHeader 组成，没有额外包一层“基础资料”总 PageHeader。本轮保持现状，测试以首个子 PageHeader 作为可见标题。
- 证照、合规和 Dashboard 的部分风险口径仍依赖现有 API 能力；无法从现有接口稳定得到的内容继续显示“待后端支持 / 数据暂不可用”，不使用假数据。

## 验证结果

- `npm run test:e2e -w @company-erp/web`：30 passed。

完整标准链和 goal-mode sweep 在 PR 前执行。

## 后续建议

- 后续 UI 切片可继续把库存入库登记等页面内长表单迁移到 `FormDrawer`，进一步减少移动端布局压力。
- 如果后端提供证照待审核、健康证缺失、保险覆盖缺口等稳定 summary endpoint，可以把 Dashboard 风险队列从“前端聚合”升级为服务端口径。
